# ADR 0021：只读系统资产关联

- 状态：接受，已实现（Phase 3 第五切片）
- 日期：2026-11-01
- 范围：软件与当前进程、服务、计划任务、启动项之间的静态路径关联
- 明确：不读取完整命令行/参数，不执行目标，不修改任何对象，不写 SQLite

## 1. 背景

Phase 3 切片 1–4 已分别建立原生防护、服务/计划任务、启动项和软件/组件的用户主动触发只读快照。用户仍需要知道一个软件条目与哪些当前对象有关，以及为什么。关联必须是可解释的静态证据，而不是名称猜测或恶意判定。

## 2. 决策

### 2.1 输入与命令

- 新增 `scan_asset_associations`，无参数，在 `spawn_blocking` 中执行。
- 复用现有只读实现：`scan_installed_software`、`list_processes`、`list_services`、`list_scheduled_tasks`、`scan_startup_items`；不新增底层扫描器，不扩大前四个切片读取的字段。
- 进程、服务、任务、启动项使用已有可执行路径/目标路径字段：
  - 进程：`ProcessSummary.executable_path`，仅 `pathAccess=available`；
  - 服务：`ServiceSummary.executable_path`（上游已丢弃参数）；
  - 任务：`ScheduledTaskAction.executable_path`（上游不读 Arguments/WorkingDirectory）；
  - 启动项：`StartupItem.target_path`（上游不读参数文本）。
- 不读取完整命令行、服务/任务/启动项参数、任务触发器或工作目录。

### 2.2 关联规则

1. **精确路径（Exact）**：规范化后的软件 DisplayIcon 路径或安装位置文件路径，与目标可执行路径完全相同。大小写不敏感，斜杠统一，去掉 `\\?\`/`\??\` 本地盘符前缀并折叠 `.`/`..`。
2. **安装目录内（Strong）**：目标是软件安装目录的后代，且路径边界正确（`C:\App` 不匹配 `C:\AppExtra`）。安装位置本身必须是文件或非宽泛的本地绝对路径。
3. **弱线索（Weak）**：仅限普通用户软件与运行进程；软件可执行文件名与进程文件名相同，但目录不同，且文件名不是系统/通用宿主名，目标不在 Windows/Program Files 系统范围。弱线索不用于服务、任务或启动项，并明确不能证明归属。
4. **宽泛根不参与归属**：磁盘根、`Program Files`、`Common Files`、`WindowsApps`、`ProgramData`、用户配置根等；直接位于 `Program Files` 下的已知厂商根也视为宽泛。安装位置/DisplayIcon 不可比较时记录 issue，不伪造路径。
5. **多候选不合并**：同一目标匹配多个软件时保留全部关系，标记 `ambiguous=true` 和候选数；不凭名称、发布者或目录深度强行选一个。
6. **不匹配不等于异常**：没有关系且来源完整为 `noMatch`；软件缺少静态路径、任一目标来源部分/不可用/截断时为 `insufficientEvidence`；全部目标来源不可用为 `sourceUnavailable`。

### 2.3 数据模型

- `AssetAssociationResult`：`observation`、五个 `AssociationSourceStatus`、`software` 摘要、`relations`、`issues`、`limitations`、`truncated`。
- `AssociationSourceStatus`：来源、观察状态、条目数、可比较路径数、未解析路径数、截断。
- `AssetRelation`：软件 ID/名称、目标（kind/ID/名称/上下文/脱敏路径/观察状态）、关系类型、证据类型、匹配方法、脱敏软件路径线索、脱敏证据值、确定性、观察状态、歧义、候选软件数、issues。
- `SoftwareAssociationSummary`：每个软件的 `linked`/`weakOnly`/`noMatch`/`insufficientEvidence`/`sourceUnavailable`、路径证据数、强/弱关系数、issues。
- 关系 ID 使用软件 ID、目标 ID、匹配方法和证据类型的稳定哈希；软件/服务/任务/启动项沿用既有稳定 ID。进程目标使用 `(pid, identity)` 只读身份令牌；无令牌时标记为部分证据，不声称跨扫描稳定。

### 2.4 隐私

- 证据值只保存脱敏路径或文件名；`C:\Users\<name>\...`（任意盘符）和本地设备前缀形式显示为 `C:\Users\***\...`。
- 不返回完整卸载命令、服务/任务参数、启动项参数、命令行或工作目录。
- 结果只在本次内存中，不新增 SQLite 表/写入，不保存到用户目录。

### 2.5 数量、时间与响应边界

- 最多 2,048 条关系、256 条弱线索、256 条/软件、32 个候选/目标。
- 证据文本最多 1,024 字符；issues 最多 256 条；所有底层来源沿用既有条目/字符串/时间上限。
- 超限/底层截断 → `truncated=true` + DataIssue；UI 明确显示“结果不完整”。
- 关联命令串行复用五个来源；本机实测约 0.5 秒，最多受各来源既有上限约束。

### 2.6 UI

- 软件详情增加“资产关联”区块；用户点击“读取资产关联”后才读取。
- 显示整体/来源观察状态、条目/可比较路径计数、当前软件摘要、按对象类型分组的证据、确定性、匹配方法、证据路径、观察状态和 issues。
- `noMatch`、`insufficientEvidence`、`sourceUnavailable` 分开显示；明确“没有关联不等于异常”。
- 不提供卸载、删除、清理、禁用、启动、停止或运行按钮；刷新失败清空旧关联结果。

## 3. 非目标

- 实时关联、跨重启归属、关联持久化/历史对比。
- 软件签名、哈希、安装来源、行为或网络关联。
- AppX/MSIX/Store/便携软件。
- 服务依赖、触发器/计划/条件、任务/启动项参数。
- 恶意性判定、告警或处置。

## 4. 后果与限制

- 关联是静态路径证据，不是“这个软件拥有这个进程/服务”的确定结论；路径可过期、可共享、可被重定向。
- 8.3 短名、junction、符号链接、环境变量和 UNC/设备路径不解析；相应来源标记未比较。
- 真实机 184 个软件条目、269 个进程、763 个服务、192 个任务、11 个启动项产生 62 条关系，其中大量软件因服务来源部分读取而显示证据不足；没有强行声称完整。
- 未实机注入来源访问拒绝、超大列表、超时、同名多候选、无效路径或并发修改；这些由自动化测试覆盖。

## 5. 验证

- Rust 测试覆盖：路径大小写/斜杠/点段/设备前缀、路径边界、同文件名不同目录、安装目录包含、服务/任务/启动项匹配、缺失任务动作、无效路径、用户目录脱敏、多候选、弱/强证据、来源不可用时状态、关系 ID/顺序稳定性和无命令字段。
- 前端测试覆盖：未读取、成功证据/脱敏、弱线索/歧义、来源不足、首次失败和刷新失败清空、无处置按钮。
- 真实非管理员探针与 release WebView2 验证见 `docs/VALIDATION.md` §24。
