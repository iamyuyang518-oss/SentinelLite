# ADR 0015：进程事件可视化

- 状态：接受，Phase 2.7 已实现并完成 Windows 实机界面验证（2026-10-31）
- 范围：`src/pages/EventsPage.tsx`、`src/lib/{processEvents,useLiveEvents}.ts`、`src/styles-phase27.css`
- 关系：消费 [ADR 0013](0013-process-event-delivery.md) 与 [ADR 0014](0014-event-persistence.md)

## 1. 背景

事件已经可以通过 IPC 读取并持久化，但用户无法在应用内查看实时事件、生命周期配对、修正历史、缺失字段和历史查询。界面不能把空数据、未知数据和正常数据混为一谈。

## 2. 决策

### 2.1 新页面

侧边栏新增“进程事件”页面，保留现有浅色纸面/仪表风格。页面分为：

- 顶部状态条：传感器连接、当前会话、数据库状态、持久化接收、最近更新。
- 异常/不确定项列表：断开、游标过期、无法解码、显示截断、会话重启、ETW 丢失、管道丢弃、解码错误、未配对/身份不确定、数据库错误、会话结束。
- 实时事件列表：来自 `get_sensor_events`，游标每 1 秒推进；有界保留 500 条。
- 生命周期详情：实时或历史事件的时间、身份、父 PID、路径、ETW 来源、配对、字段完整性。
- 历史查询：SQLite 时间范围、名称/路径、PID、类型、会话筛选；100 行分页。
- 行为分析面板（见 ADR 0016）。
- 本地数据状态：路径、主文件+WAL 大小、计数、保留策略、持久化错误。

### 2.2 实时与历史的区别

- 实时列表只显示当前传感器会话的投递窗口；传感器重启会清空并明确提示。
- 历史列表只来自 SQLite；不把实时内存数据伪装成已持久化。
- 历史数据可能滞后于实时数据；历史查询不自动轮询，用户主动查询/刷新。
- 选择实时事件显示当前列表中的配对；选择历史事件通过 `get_stored_event` 读取原始记录、配对事件、修正历史和 `SessionEnd`。

### 2.3 状态语义

- 传感器断开时保留最后事件，但显示“传感器未连接；不能当作当前完整的进程活动”，不显示为健康空列表。
- 游标过期显示缺失条数；显示截断显示已移除条数；ETW 丢失未知显示“未知”而不是 0。
- 配对修正到达后更新对应退出事件；历史详情显示修正来源。
- 缺少父 PID/映像/时间显示“未提供/时间未知”，不补默认值。
- 身份不确定显示原因；不按 PID 推断关联。
- 会话没有 `SessionEnd` 时显示“未观察到结束”，不显示为正常完成。

### 2.4 数据真实性

截图和文档使用真实传感器/数据库运行数据；测试使用明确虚构 fixture，不进入产品界面。页面不包含演示数据、随机数据或“模拟运行”开关。

### 2.5 明确不做

- 不提供告警队列、威胁评分、拦截、结束进程、删除文件或自动处置。
- 不显示未经读取的原生防护状态或整体“保护正常”。
- 不把单条事件标记为恶意。
- 不新增网络请求或远程字体/图表依赖。

## 3. 后果

优点：

- 用户能看到真实事件、配对修正、缺失字段和数据缺口。
- 实时与历史来源清晰分离。
- 断开、过期、未知和正常有不同视觉/文字状态。

限制：

- 实时列表只保留 500 条；完整历史依赖 SQLite。
- 实时列表依赖传感器运行；应用未运行时只能查询历史。
- 行内事件表没有虚拟滚动；500 条上限控制渲染成本。
- 页面每 1 秒轮询一次事件；传感器断开时轮询继续按退避重试。

## 4. 验收

- 前端测试：实时合并/去重/修正、游标过期、会话重启、500 条上限、历史筛选/分页/详情、断开与未知状态、分析结果与证据跳转。
- 真实 Windows：应用窗口最终截图显示真实会话 170 条实时事件（较早长会话截图为 166 条）、会话已结束、数据库正常、持久化运行中；历史查询截图时显示 371 条/3 个会话，最终数据库 1009 条/11 个会话；点击“分析会话”显示真实 `PROC-BURST-001` 结果和证据事件 ID。截图见 `docs/screenshots/events.png` 和 `events-analysis.png`。
