# ADR 0022：只读安全态势整合

- 状态：接受，已实现（Phase 3 第六切片）
- 日期：2026-11-01
- 范围：把 Phase 3 切片 1–5 的原生防护、软件、进程、服务、计划任务、启动项与静态路径关联整合为一个可解释的用户视图
- 明确：不新增扫描器、Tauri command 或 SQLite 持久化；不提供安全评分、处置或恶意软件判定

## 1. 背景

切片 1–5 已分别提供原生防护快照、服务/计划任务、启动项、软件/组件和软件资产关联。用户仍需要在同一处理解：

- Defender/防火墙哪些字段已读取、哪些未知；
- 五个资产来源是否完整；
- 哪些软件与进程、服务、计划任务或启动项有路径证据；
- 哪些线索只是弱线索或多候选；
- 哪些对象因为来源不完整而无法判断。

把每项结果简单相加或生成 0–100 分，会把“已启用”“未知”“部分读取”“来源不可用”和“没有关联”混为一谈。本切片的目标是解释证据，而不是给出虚假的整体安全结论。

## 2. 决策

### 2.1 页面与状态复用

- 在“软件体检”页面顶部增加“安全态势概览”，位于原有“软件盘点/启动项/服务与计划任务/进程与亲和性”标签之前。
- 用户主动点击“读取安全态势”时，一次读取：
  - `get_native_protection_status`
  - `scan_asset_associations`（内部复用软件、进程、服务、计划任务、启动项五个只读快照）
- 不新增底层扫描器、不新增 Tauri command、不新增 capability。
- 原生防护快照由应用壳层的单一 `ScanController` 管理，首页卡片和软件体检页共用，不因页面切换重复读取。
- 资产关联快照在“软件体检”页面内只创建一个 `ScanController`，概览和软件详情共用。软件重新盘点时清空旧关联，防止旧快照被展示为最新结果。

### 2.2 数据读取状态

概览只使用以下读取状态描述数据可读性：

| 状态 | 含义 |
| --- | --- |
| `notRead` | 尚未读取 |
| `complete` | 作用域内来源均已读取，且未截断 |
| `partial` | 至少一个来源部分读取、字段未知或结果截断 |
| `unavailable` | 没有可用来源，或命令失败 |

这些状态不是安全状态。`complete` 不表示系统安全或防护有效。概览不生成百分制分数，也不显示“保护正常”。

### 2.3 线索分类

概览用四个分类展示当前证据边界：

- **已观察事实**：精确路径、安装目录内路径、已启用防护开关、已读取来源；
- **值得核实**：弱线索、多候选、未启用防护开关；
- **证据不足**：证据不足的软件、未知防护字段、部分读取来源、观察不完整的关系；
- **来源不可用**：来源不可用的软件、资产来源和防御提供程序。

分类计数只用于解释观察结果，不把陌生软件、第三方组件、未关联进程或未启用开关直接判为恶意。

### 2.4 防护状态

- 保留 Defender 防病毒、实时保护、反恶意软件服务、签名版本/年龄，以及三个防火墙配置文件。
- `enabled`、`disabled` 和 `unknown` 分开显示；未知不会回退为已启用或未启用。
- 未启用的反恶意软件服务与其他未启用开关一样被明确列出；修复了 Slice 1 中 `amServiceEnabled=false` 时仍显示“已读取到的开关均为启用状态”的 P2 摘要问题。
- 即使读取到的开关全部启用，也只说明当前快照中的开关状态，不验证实际拦截能力、规则完整性、排除项、ASR、篡改保护或第三方 AV。

### 2.5 资产关联证据

- **持久化入口区块**展示计划任务与启动项关系；服务归入进程/服务区块，避免服务在持久化区块重复出现。
- **进程与服务区块**展示运行进程和 Windows 服务关系；每个关系都带匹配方法、确定性、观察状态、来源、证据类型、证据路径和软件路径线索。
- **弱线索与多候选区块**是交叉筛选，可能和上方列表重复；界面明确说明重复原因，不把弱线索升级为确定归属。
- **软件关联状态区块**保留 `linked`、`weakOnly`、`noMatch`、`insufficientEvidence`、`sourceUnavailable` 的区分，并展示前 8 个有路径线索的软件。
- 关系列表默认显示前 6 条，其余在可展开的详情中显示；不改变证据内容，也不把隐藏项当作不存在。
- 用户目录路径在前后端都脱敏；不读取完整命令行、服务/任务参数、任务触发器或启动项参数文本。

### 2.6 刷新、失败与快照语义

- 所有读取由用户主动触发；没有后台轮询或自动刷新。
- 读取失败时 `useScanAction` 清空旧结果，概览按来源显示“未保留上一次结果”，不会把旧快照伪装成新结果。
- 概览明确标注数据为当前快照；系统状态变化后结果可能过期。重新读取是唯一更新方式。
- 概览不因一个来源失败而清空另一个来源的结果；每个来源独立呈现。

## 3. 非目标

- 0–100 安全评分、整体“保护正常/已受保护”状态。
- 恶意软件判定、自动告警或任何处置按钮。
- 新增文件/网络/DLL/服务持续监控。
- 实时关联、跨重启归属、关联历史持久化或完整资产图。
- AppX/MSIX/Store/便携软件、签名/哈希行为关联。
- 为关联覆盖率修改前四个切片的数据采集范围。

## 4. 后果与限制

- 概览只是现有五个只读快照与原生防护快照的前端组合；不证明系统安全，也不证明没有隐藏组件。
- 来源部分读取时，171 个软件可能显示证据不足；这是真实的数据缺口，不是“无关联”或“安全”。
- 真实机关系数量随当前进程变化；同一只读命令在不同时刻可能得到不同条数。
- 弱线索、多候选和来源不可用路径由自动化测试覆盖；真实机没有弱线索/多候选样本。
- 静态路径可能过期、共享或被重定向；不验证存在性、签名、哈希或行为。

## 5. 验证

- 前端测试覆盖：未读取、组合读取、五来源状态、原生防护未知/未启用/部分读取、弱线索/多候选、noMatch 与 insufficient 的区分、刷新失败清空、共享快照、无处置按钮和用户路径脱敏。
- 真实 release WebView2 验证：68 条关系（49 进程、11 服务、8 计划任务/启动项），13 个软件有线索、171 个证据不足、0 个未匹配；3 个来源已读取、2 个部分读取、0 个不可用；原生防护 6 个开关已读取，0 个未启用。
- 真实 UI 未出现原始用户路径、卸载命令、处置按钮或“保护正常/已确认威胁”；UI Automation 检查 PASS。详细证据见 [VALIDATION](../VALIDATION.md) §25。
