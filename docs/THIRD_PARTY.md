## License review

The project itself is MIT-licensed. The direct dependencies are permissive or dual-licensed with a permissive option. The generated inventory currently lists 232 npm packages and 403 Cargo packages, with 0 missing license fields, 31 packages requiring manual review, and 0 automatically blocked strong-copyleft/source-available expressions. It contains:

- **MPL-2.0** transitive packages (for example `cssparser`, `selectors`, `dtoa-short`, `option-ext`, and the npm `lightningcss` build package). This public release is source-only and distributes selected exact-version source archives with the MPL text and a dedicated source-only notice. It does not distribute an Executable Form, so MPL Section 3.2 is not triggered by this repository; a future binary release must preserve notices and make the MPL-covered source available as required. The project has not performed a complete legal review.
- **CC-BY-4.0** data (`caniuse-lite`, used by the frontend build toolchain). Attribution is required if the data is redistributed; it is not part of the application's runtime logic.
- **Unicode-3.0** packages (ICU and related crates) and **Zlib** packages. These are permissive but may require notice retention.
- **BlueOak-1.0.0** packages (`lru-cache`, `minimatch`) in the JavaScript toolchain.
- **LGPL-2.1-or-later as one option** for `r-efi`; the project selects the MIT/Apache-2.0 option and does not rely on the LGPL branch.
- No GPL, AGPL, SSPL, Commons Clause, Business Source, or Elastic License expression was detected by the automated scan.

This is an engineering review, not a legal opinion. For this source-only release, keep the source-only license notice, exact source archives, per-package notices, and source SBOM together. A future binary distribution must separately confirm MPL Section 3.2, native-binding, and CC-BY attribution obligations. The generated bundle is available:

## Vulnerability and advisory checks

### npm

`npm audit` on the full dependency tree currently reports **11 moderate** findings, all in the development/building toolchain through `minimatch` via ESLint and TypeScript ESLint. There are **0 high** and **0 critical** findings. `npm audit --omit=dev` reports **0** production vulnerabilities. `npm audit --audit-level=high` passes.

The suggested automatic fix would downgrade ESLint to an old major version and is not applied. The moderate development findings are tracked as a maintenance item; they do not affect the packaged runtime dependencies.

### Cargo

A local **RustSec advisory-db cross-check** was performed on 2026-11-02 using advisory-db commit `263a4d951a0867d4bddc29dddd6d59427c78f9a7` (1382 advisory files). The official `cargo-audit` CLI could not be built in this environment because its `aws-lc-sys` dependency requires CMake/NASM and the crate download stalled; this is a manual cross-check using the same RustSec data, not a substitute for `cargo-audit`.

Findings matched to `Cargo.lock`:

| Package | Version | Advisory | Type | Dependency path | Patched |
| --- | --- | --- | --- | --- | --- |
| `quick-xml` | 0.38.4 | RUSTSEC-2026-0194 | Denial of service (quadratic attribute check) | `plist` -> `tauri-utils` -> `tauri` | `>=0.41.0` |
| `quick-xml` | 0.38.4 | RUSTSEC-2026-0195 | Denial of service (namespace allocation) | `plist` -> `tauri-utils` -> `tauri` | `>=0.41.0` |
| `time` | 0.3.45 | RUSTSEC-2026-0009 | Denial of service (RFC 2822 stack exhaustion) | `cookie`/`plist` -> `tauri` | `>=0.3.47` |

No SentinelLite code path parses user-supplied XML or user-supplied RFC 2822 date strings; the advisories are in transitive Tauri/plist/cookie dependencies and are assessed as low-exposure availability risks for this application. This is not a proof that the paths are unreachable in every WebView2/Tauri code path.

Informational findings: `glib 0.18.5` is marked unsound (GTK/Linux path, not part of the Windows runtime used here), and `proc-macro-error 1.0.4` is unmaintained (build-time proc-macro). They are recorded but are not counted as runtime vulnerabilities.

A targeted resolver check showed that `cargo update -p plist --precise 1.10.3` would bring `quick-xml 0.42.0` and `time 0.3.55` and would require Rust 1.88 (the workspace currently declares `rust-version = "1.85"`). This update was **not applied**: it raises the MSRV and needs a full Tauri compatibility/test/build pass. Do not upgrade blindly to make the advisory list disappear.

## Distribution notes

- Source builds use `Cargo.lock` and `package-lock.json`; both must be committed.
- CI regenerates [THIRD_PARTY_INVENTORY.md](THIRD_PARTY_INVENTORY.md) and fails if the committed inventory differs.
- Binary distributions must include the generated license bundle under `third-party-licenses/`, the MPL source materials under `third-party-source/mpl/`, and the applicable SBOM/material notes.
- CycloneDX source and binary-composition SBOMs are now generated. There is still no reproducible-build proof, signed-update chain, or legal review.
- No prebuilt binary, driver, or telemetry SDK from an unknown source is used.

## Update process

1. Change dependencies and commit the updated lockfiles.
2. Run `npm run licenses` with Cargo in `PATH`.
3. Review the generated diff and any newly introduced license expressions.
4. Run `npm audit --audit-level=high` and a Cargo advisory audit.
5. Review notices and distribution obligations before publishing a binary.
6. CI checks that the generated inventory is committed.

Passing the automated script does not mean "all dependencies are risk-free" or that a legal audit has been completed.
