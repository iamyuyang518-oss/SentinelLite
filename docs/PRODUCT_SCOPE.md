# 产品范围

## 愿景

SentinelLite 为 Windows 10/11 用户提供一个本地优先、可解释、可恢复的安全体检工具。它应该帮助用户理解：

- 系统里有什么软件、启动项与持续运行的组件；
- 有哪些可观察证据支持风险判断；
- 哪些内容没有检查、没有权限检查或无法确认；
- 下一步如何验证，而不是被诱导执行不可逆操作。

核心原则：

1. **未知风险不能默认视为安全。**
2. **监控失效不能显示为正常。**
3. **无法确认的异常不能伪装成确定的病毒判定。**
4. **清洗操作的默认方向是只读、可逆和用户可控。**
5. **与原生安全产品协作，不在第一版取代成熟杀毒引擎。**

## 目标用户

- 发现电脑变慢、广告弹窗、浏览器主页被改、启动项异常，但不知道从哪里查起的 Windows 用户。
- 希望看到证据和限制，而不是只得到“安全/危险”二选一结论的用户。
- 愿意在知情前提下手动调查和处置本机软件的用户。

它不是面向企业 SOC 的 EDR，也不面向需要实时阻断的高级攻击场景。

## 四大组成部分与当前状态

| 组成 | 目标 | v0.1.0 状态 |
| --- | --- | --- |
| 日常实时安全监控 | 持续采集进程、文件、网络、持久化与原生防护状态 | **进程部分实现，原生防护/服务/任务按需只读**：独立管理员传感器采集进程 start/stop，完成标准化、配对、有界排队和游标事件投递；主应用接收并持久化事件，提供实时/历史事件页和基础行为分析；Phase 3 切片 1 增加 Defender/防火墙只读快照，切片 2 增加服务与计划任务只读盘点。尚未覆盖文件/网络/DLL/持续服务/任务监控，没有策略审计或实际拦截验证，尚无告警或处置；整体保护状态仍为未知 |
| 深度防御模式 | 用户定时开启的更高粒度观察与关联分析 | **未实现** |
| 软件体检与清洗 | 软件/启动项/残留盘点、证据化风险与受控处置 | 只读盘点、静态路径关联、安全态势只读整合与部分检查已实现；处置未实现 |
| 告警、解释与恢复 | 统一事件模型、审计、可恢复操作 | 已实现进程事件模型、IPC、SQLite 历史、配对修正、可解释基础规则；告警队列、恢复快照和处置未实现 |

## “软件体检与清洗”的产品定位

它不是“软件卸载列表”或“垃圾清理器”，而是：

- 用可追溯的数据源盘点软件与关联项；
- 将软件、启动项、服务、计划任务和残留之间建立有证据的关联；
- 区分恶意软件、潜在不受欢迎软件、推广组件、用户不需要的正常软件和配置异常；
- 优先调用软件自己的卸载入口与 Windows 原生功能；
- 在执行前展示影响、可逆性和恢复方案；
- 对无法确认的内容明确标为未知或证据不足。

第一阶段先建立数据、证据和状态模型；**任何清洗操作均不在当前版本范围内**。

## 状态语义

保护状态必须由监控事实驱动，不能由 UI 装饰或默认值驱动。

| 状态 | 含义 | v0.1.0 行为 |
| --- | --- | --- |
| 保护正常 | 关键监控正常，已知覆盖范围内没有待处理高风险告警 | **代码中不提供该状态**：首页仅显示独立传感器的健康字段；整体保护正常仍必须由 ADR 0008 的 health model 引入 |
| 发现风险 | 已发现需要调查或处置的可疑行为 | 只读检查条目会显示条目级风险；首页整体状态仍为未知 |
| 保护降级 | 关键传感器异常、权限缺失、事件丢失或覆盖受损 | 首页可显示传感器 Active + 健康异常/降级；整体保护状态仍为未知 |
| 状态未知 | 尚无充分证据证明监控正常 | 首页整体保护状态的唯一实际输出 |

首页会在后端不可用、DLL/设备无响应或 IPC 错误时保持整体“状态未知”，不会退化为绿色“保护正常”。传感器查询失败时，传感器区域显示不可用/健康未知并清空旧计数，不保留上一次的健康结果。Phase 1.1 已删除 `ProtectionState::Protected`，任何未来重新引入都必须基于真实传感器健康模型。条目级风险判断与首页保护状态不是同一概念。

风险等级：

1. 已确认威胁
2. 高风险可疑行为
3. 潜在不受欢迎软件
4. 用户不需要的软件或推广组件
5. 配置异常，原因待确认
6. 检查范围内未发现异常（只限定于当前证据作用域）
7. 检测证据不足

每条风险都带 `scope`（软件元数据、启动项元数据、亲和性配置、进程整体）。`NoClearIssue` 使用中性样式，不是绿色“安全”。v0.1.0 的规则不会产生“已确认威胁”。单一路径、缺少签名、软件名称或品牌不能作为定罪依据。

## 第一阶段范围（v0.1.0）

已纳入：

- 项目结构、Rust core 与 Tauri 命令边界。
- 产品、威胁模型、清洗规范、架构、能力边界和路线图文档。
- 首页、软件体检页和证据面板；所有未实现能力显式标注。
- 只读软件盘点（HKLM 32/64 位视图 + HKCU 单一共享视图；来源/条目观察状态、字段状态、有界条目/字符串上限）。
- 软件分类语义：UserSoftware、SystemComponent、DriverOrHardwareComponent、RuntimeOrSharedComponent、SecuritySoftware、Unknown；分类字段保留 present/missing/typeMismatch/invalid/readError 状态，无法确认时保持 Unknown，并对系统/组件条目使用不同风险语义。
- 软件字段：DisplayVersion、Publisher、InstallDate、DisplayIcon 静态路径线索、WindowsInstaller、卸载入口存在性；不返回完整卸载命令。
- 只读启动项检查（Run、RunOnce、用户与所有用户启动文件夹）；保留注册表值类型、来源/条目观察状态和 Raw Value 可读性；区分 Present/Missing/AccessDenied/Unknown 与未加引号歧义路径；`.lnk` 只读目标与参数/工作目录存在性布尔值；desktop.ini/Thumbs.db 等文件夹元数据不计为启动项。
- 有界只读进程快照（最多 2048 项；名称/路径有长度上限）、创建时间身份绑定、CPU 亲和性、磁盘签名/元数据/SHA-256 和短时 CPU 采样。
- 亲和性专项结论与整体进程结论分离；没有行为证据时整体结论为证据不足。
- 证据、规则 ID、置信度、盲区和检查时间。
- 虚构数据单元测试与真实主机只读冒烟验证。

Phase 2.5–2.8 已补充纳入：

- 标准化进程事件的只读游标 IPC、配对修正和 `SessionEnd` 交付。
- 主应用本地 SQLite 事件历史（幂等、有界查询、保留策略、schema 迁移）。
- 实时/历史事件页面、生命周期详情、异常/数据缺口展示。
- 可解释的进程行为规则（频率、配对覆盖、生命周期一致性）和输入质量门禁。

Phase 3 切片 1 已补充纳入：

- 用户主动触发的 Defender（开关/签名）和 Windows 防火墙（三个配置文件）只读快照。
- 字段缺失、无权限、提供程序缺失和查询失败分别显示为部分/未知；不改变整体保护状态。
- 只读、不写策略、不起子进程、无后台轮询。

Phase 3 切片 2 已补充纳入：

- 用户主动触发的 SCM 服务与 Task Scheduler 计划任务只读盘点。
- 服务显示状态/启动类型/类型/账户/可执行路径；任务显示状态/启用位/作者/运行身份/动作可执行路径。
- 单条/单文件夹失败保持部分/无权限；数量、时间和字符串上限；结果仅在内存，不写 SQLite。

Phase 3 切片 3 已补充纳入：

- 用户主动触发的 Run/RunOnce 与启动文件夹只读盘点；保留注册表值类型、来源/条目观察状态和 Raw Value 可读性。
- `.lnk` 通过只读 ShellLink 读取目标与参数/工作目录存在性布尔值；不读取参数文本、不调用 Resolve、不执行目标。
- 来源不存在与无法读取分开；单个来源/条目失败不影响其他来源；结果仅在内存，不写 SQLite。

Phase 3 切片 4 已补充纳入：

- HKLM 32/64 与 HKCU Uninstall 来源级/条目级观察状态；字段只读类型/值/读取状态。
- DisplayVersion、Publisher、InstallDate、DisplayIcon 静态路径线索、WindowsInstaller；卸载入口只判断是否存在，不返回或执行完整命令。
- 安装路径 UI 脱敏；不合并不同来源的同名登记记录；无 DisplayName 注册项跳过并计数。

Phase 3 切片 5 已补充纳入：

- 用户主动触发的软件→进程/服务/计划任务/启动项静态路径关联；精确路径、安装目录包含和同名文件弱线索分开标注。
- 每个关系记录证据、匹配方法、确定性、观察状态、候选歧义和 issues；宽泛根不作为归属证据，多候选不强行合并。
- 来源部分/不可用/截断显示证据不足，不显示为“没有关联”；用户目录脱敏，不读取命令行/参数，不执行目标，不写 SQLite。

Phase 3 切片 6 已补充纳入：

- “软件体检”顶部的安全态势概览；复用原生防护和资产关联快照，不新增扫描器或 Tauri 命令。
- 分开显示 `notRead`、`complete`、`partial`、`unavailable` 和防护开关的 enabled/disabled/unknown；不提供 0–100 分数或整体“保护正常”。
- 将线索分为已观察事实、值得核实、证据不足、来源不可用；展示持久化入口、进程/服务关系、弱线索/多候选和软件关联状态。
- 概览与软件详情共享同一份关联快照；应用壳层共享原生防护快照；刷新失败清空旧结果，不把旧快照显示为最新结果。
- 不提供处置按钮，不读取完整命令行/参数，不新增持久化、提权或联网能力。

0.1.0 不提供应用内启动传感器或 UAC 提权入口；独立传感器必须由管理员在应用外从源码构建并手动启动。本次 source-only 发布不提供安装包或传感器二进制；本地构建的安装包不包含该二进制，主应用也不能启动、停止或配置传感器。

当前仍明确不含：

- 任何写操作、卸载、删除、进程终止、服务启动/停止/创建/删除/修改、任务运行/创建/修改/删除/启用/禁用、亲和性修改或自动处置。
- 0–100 安全评分、整体“保护正常/已受保护”判定；不把陌生软件、未关联对象、未启用开关或第三方组件直接判为恶意。
- 文件/网络/DLL/服务/计划任务持续监控、告警队列、通知。
- AppX/Store 应用、浏览器扩展、卸载残留关联；实时/跨重启资产关联、持久化关联历史和行为关联尚未实现。
- 服务触发器/计划/条件/上次运行结果、任务 Arguments/WorkingDirectory、启动项快捷方式参数/工作目录文本、`.url`/MSI 通告式快捷方式目标、目标文件签名/哈希。
- Defender/防火墙的持续监控、策略/规则审计、第三方 AV SecurityCenter2 和实际拦截验证。
- 深度防御模式和自动响应。
- YARA-X/Sigma 规则集成、文件内容扫描、恶意样本检测率。
- 二进制安装包签名、自动更新和未来二进制正式发布。

## 第二阶段的前置条件

在加入任何处置能力之前，必须先满足：

1. 有可验证的软件→启动项/服务/计划任务静态关联模型，并明确证据等级、来源不完整和歧义；实时/持久化关联仍需后续补齐。
2. 有持久化审计记录与恢复快照设计。
3. 每个动作有预览、用户确认、执行验证和失败回滚/报告。
4. 对误报与正常软件案例建立回归测试。
5. 对动作使用显式白名单和参数校验，禁止前端提供任意命令或路径。
6. 用户可查看并删除本地审计数据。
7. 通过独立安全评审；不得暗示已通过完整安全审计。

性能目标（日常 CPU < 2%、内存 < 100 MB）仍是后续优化目标。当前一次 release 首页空闲采样的总进程树内存高于 100 MB；具体数值、硬件和局限见 [VALIDATION.md](VALIDATION.md)。任何资源数据都必须附参考硬件、负载和测量方式，不能用主进程单值替代整个进程树。

## 产品语言规范

- “检查范围内未发现异常”后面必须跟着作用域说明；不能写成“安全”，UI 不得使用绿色 clean 语义。
- “未签名”不能等于“恶意”。
- “签名有效”不能等于“行为安全”。
- “亲和性受限”不能等于“恶意绑定”。
- “高 CPU”不能等于“被修改亲和性”。
- “有启动项”不能等于“会运行”，更不能等于“病毒”。
- “无法读取/AccessDenied”必须显示为未知、权限不足或证据不足，不能默认为不存在或正常。
- 达到条目/字符串/进程快照上限时必须显示“结果不完整”，不能声称完整盘点。
- 磁盘签名和 SHA-256 不能证明内存映像或运行进程绝对可信。
- 清理入口必须区分“官方卸载”“禁用自启动”“删除残留”和“终止进程”，不能用模糊的“一键优化”。

## 隐私和权限

默认本地处理；当前版本不发起网络请求。进程事件历史保存在当前用户本地 SQLite，不加密、不上传，默认保留 30 天/1,000,000 条/512 MiB；应用未运行时不写入历史。前端没有 Shell、任意文件读写或 HTTP 能力。后台组件与 UI 的边界通过固定 Tauri 命令的 application-level ACL 与 `generate_handler!` 双重维护；命令只接受数值 PID/游标/受限过滤条件，原生防护查询无参数，不接受路径、命令或脚本。

独立 `SentinelLiteSensor` 是需要管理员权限的只读 ETW 传感器（见 ADR 0010），通过受限 Named Pipe 提供只读状态和只读事件批次（见 ADR 0011/0013）。主应用以普通用户连接，不能启动、停止、配置或控制传感器；没有把管理员 Shell 暴露给 UI。0.1.0 不提供应用内启动传感器或 UAC 提权入口，传感器必须由管理员在应用外手动启动。行为分析只产生本地结果，不执行任何系统操作。
