# 清洗与恢复规范

当前版本（v0.1.0）**没有任何清洗动作**。本文件定义未来动作功能的硬性规范，也是当前代码审查的边界：任何违反这些原则的 PR 默认不合并。

## 1. 核心原则

1. 优先只读检查；其次调用软件官方入口；最后才考虑可逆的、范围明确的修改。
2. 任何高影响动作必须可预览、可确认、可审计，并尽可能可撤销。
3. 不得把“未知”“证据不足”当作自动处置的理由。
4. 不得根据病毒名称、品牌、文件名、是否签名等单一信号执行不可逆操作。
5. 不得自动卸载由系统或其他软件共享的组件、驱动、运行库。
6. 不得为了提高“清理数量”而放宽安全条件。
7. 不能可靠撤销的动作必须明确标记，并在执行前单独确认。

## 2. 动作等级

| 等级 | 示例 | 默认策略 |
| --- | --- | --- |
| A. 只读 | 盘点、读取启动项、签名状态、亲和性 | 可自动执行（仍由用户触发） |
| B. 官方卸载 | 调用软件正式卸载入口 | 仅用户选择；预览命令、发布者、影响；不自动静默卸载 |
| C. 可逆配置修改 | 禁用用户启动项（有恢复快照） | 后续阶段；用户逐项确认；记录原值 |
| D. 不可逆处置 | 删除残留文件/注册表、隔离文件 | 后续阶段高门槛；逐项确认、范围证明、独立审计 |
| E. 进程终止 | 结束有明确风险证据的进程 | 后续阶段受控操作；不能作为默认清理动作 |
| F. 禁止 | 批量删除未知文件、批量删注册表、关闭安全功能 | 永不默认提供；需要独立产品决策与审阅 |

第一阶段只支持 A。B–F 都不应出现在 UI 或后端命令中。

## 3. 分类与可执行动作

| 风险分类 | 可否自动处置 | 允许的人工后续动作 |
| --- | --- | --- |
| 已确认威胁 | 否 | 未来由受控清洗流程处理；第一版不产生此分类 |
| 高风险可疑行为 | 否 | 调查证据、查看来源、使用官方安全产品扫描 |
| 潜在不受欢迎软件 | 否 | 用户核实后使用官方卸载入口 |
| 用户不需要的软件 | 否 | 用户主动选择卸载 |
| 配置异常，原因待确认 | 否 | 先查清原因；可考虑禁用一个非关键启动项，但需快照 |
| 检查范围内未发现异常 | 否 | 无需动作；该结论有 scope，不能升级为清理目标 |
| 检测证据不足 | 否 | 补足证据或保持未知；不得以清理作为“修复” |
| 系统/组件类条目 | 否 | 不按普通软件卸载；需要独立组件关联与明确证据 |

## 4. 未来可逆动作必须满足的条件

每个动作必须包含：

1. **范围证明**：目标 ID、注册表键/值、磁盘哈希和创建时间进程身份令牌；禁止关键字/通配符/全盘遍历匹配。PID 或显示名称本身不足以作为身份。
2. **影响预览**：将修改什么、会影响哪些用户/软件、是否共享组件、是否需要重启。
3. **明确确认**：默认不是选中状态；用户逐项确认；不可逆动作需要二次确认，不能与其他动作捆绑。
4. **执行前快照**：保存原注册表值、文件元数据或可恢复副本的受控引用；记录快照位置、创建时间和完整性校验。
5. **最小操作**：只调用软件官方卸载入口或必要的单点 API；不启动任意 Shell，不接受前端传入的命令字符串。
6. **结果验证**：检查动作是否实际完成，区分成功、失败、部分完成、重启后生效。
7. **恢复路径**：提供恢复操作、恢复前提、失败回滚和不可恢复提示。
8. **审计记录**：本地记录动作 ID、目标、前后状态、时间、结果和恢复状态；用户可查看、删除。
9. **权限分层**：UI 不直接持有管理员能力。未来若需要高权限，使用独立受控代理、操作白名单、参数校验和签名/本地校验，不开放通用命令执行。
10. **用户数据保护**：不删除用户文件、共享运行库、驱动、系统组件、凭据或浏览器数据。

## 5. 卸载流程要求

- 优先使用注册表提供的官方 `UninstallString`/`QuietUninstallString`，但**前端只选择已解析的软件条目**，不提交任意命令。
- 执行前展示发布者、版本、安装位置、卸载命令的可读解释和可能保留的数据。
- 不静默调用卸载器；不使用 `/S` 等静默参数，除非用户明确选择并理解。
- 卸载完成后单独检查残留；残留不是自动删除的授权。
- 软件与系统组件共享的文件、驱动、运行库绝不当成“垃圾”删除。
- 软件占用资源不是卸载理由；必须由用户决定。

## 6. 启动项和不需组件

- 读取 Run/RunOnce/启动文件夹不等于确认实际启用；Windows 启动审批状态需要额外核验。
- 后续若允许禁用，必须保存原注册表值/文件属性和审批状态，提供恢复。
- “用户标记为不需要”不等于恶意，不得自动卸载。
- 不得默认禁用系统服务、安全软件或驱动相关启动项。

## 7. 处理器亲和性

- 第一版只读，不提供“修复亲和性”按钮。亲和性结论只属于 `affinityConfiguration` scope，不能作为进程整体结论。
- 亲和性受限不是恶意证据；高 CPU 也不是。正常亲和性也不能证明进程整体安全。
- 未来若提供恢复设置，必须：
  - 确认目标进程身份（PID + 创建时间/路径）；
  - 保存原掩码；
  - 由用户选择特定进程；
  - 说明可能影响性能和软件行为；
  - 验证新掩码并允许恢复；
  - 绝不批量修改所有进程。
- 不声称能够追踪此前是谁修改了亲和性，除非操作系统提供可验证的审计来源。

## 8. 事件与审计结构（未来）

统一事件记录至少包含：

- 事件 ID、UTC 时间、操作会话 ID；
- 数据来源与传感器状态；
- 规则 ID、风险等级、置信度；
- 进程/文件/注册表对象的最小标识与证据；
- 已知盲区与被抑制的规则；
- 建议动作、用户决定、执行结果、验证结果；
- 恢复快照引用与完整性校验；
- 不可撤销标记。

## 9. 测试门槛

每个写动作合并前必须包含：

- 正常路径、权限不足、目标已不存在、目标身份变化、部分成功；
- 回滚成功、回滚失败、重启后恢复；
- 共享组件/系统组件保护；
- 误报场景和用户取消；
- 前端没有自动批量执行路径；
- 审计记录可核查且不包含不必要的敏感数据。

在上述门槛满足之前，`v0.1.0` 的只读边界不得扩大。
